# Epic AP2 — Run and learn loop

## Objective

After changing **project configuration**, an agent builder can **run** automated play against the game and **see results** clear enough to **learn** what to adjust next.

## Scope

- Observable **configure → run → results → iterate** behavior.
- **Actionable** feedback when a run cannot complete or the game is unavailable—without raw engineer-only dumps as the only signal.

## Dependencies

- **AP1** clarity helps Avery interpret outcomes; can overlap in delivery order but AP2 assumes Avery knows **what they changed**.
