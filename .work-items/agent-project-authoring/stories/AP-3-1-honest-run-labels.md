# AP-3-1 — Honest run labels

## Epic

[AP3 — Trust and honest labels](../epics/AP3-trust-and-honest-labels.md)

## User persona

See [persona.md](../persona.md) — **Agent builder Avery**.

## User story

**As an** agent builder Avery
**I want** each automated run to be **labeled** in **plain language** so I know whether behavior is **scripted or fixed**, **lightly guided**, or **more adaptive**
**so that** I am never misled into thinking the system is “fully playing on its own” when it is not

## Acceptance criteria (EARS)

- **WHEN** I start or view a run **THEN** I **SHALL** see **how to read** that run (what kind of automation it is) using **consistent vocabulary** across the product for that mode.
- **IF** the product offers more than one **run style** **THEN** I **SHALL** be able to **tell which style** is active **before** I invest time interpreting results.
- **WHEN** a run uses **deterministic or repeating** behavior **THEN** the labeling **SHALL** make that clear **without** insider jargon.

## Success metrics (verifiable)

- Labels and modes can be **checked** in review for consistency with [index.md](../index.md) marketing principles (**accurate**, **consistent**).
