# AP-1-1 — What you defined is clear

## Epic

[AP1 — Your configuration is clear](../epics/AP1-your-configuration-is-clear.md)

## User persona

See [persona.md](../persona.md) — **Agent builder Avery**.

## User story

**As an** agent builder Avery
**I want** to see **what is mine**—prompts, agent behaviors, and reactions I put in **project configuration**—versus what the **shared experience** always provides
**so that** I can reason about outcomes without guessing which layer produced them

## Acceptance criteria (EARS)

- **WHEN** I open or review my authoring workspace **THEN** I **SHALL** be able to tell **what I configured** apart from **what everyone gets** from the standard shell or shared defaults.
- **WHEN** I look for where my **definitions** live **THEN** I **SHALL** find them grouped or labeled so I do not confuse them with **fixed product chrome** (status, layout, or shared controls).
- **IF** the product surfaces both **my definitions** and **shared guidance** **THEN** I **SHALL** see **plain-language cues** (titles, sections, or labels—not implementation names) that preserve that distinction.

## Success metrics (verifiable)

- Reviewers can trace each criterion to **observable copy or layout** in the eventual authoring experience without referencing source file names or protocols.
